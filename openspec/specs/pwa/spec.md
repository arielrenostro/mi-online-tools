# pwa Specification

## Purpose
The app is an installable Progressive Web App that keeps working offline: its shell is precached by
a service worker, so after the first visit it opens without network. All data already lives in the
browser (see `session-persistence`), so nothing else is needed for offline use.

## Requirements

### Requirement: Web app manifest
The app SHALL publish a web app manifest (`manifest.webmanifest`, generated by `vite-plugin-pwa`
from `vite.config.ts`) declaring name "Master Injection Online Tools", short name "MI Tools",
`display: standalone`, `start_url`/`scope` `/`, dark background/theme color (`#030712`) and icons
192×192, 512×512 and a 512×512 `maskable` one (all in `public/`).

#### Scenario: Browser offers installation
- **WHEN** the user opens the app over HTTPS (or localhost) in a browser that supports installation
- **THEN** the browser offers to install it, and the installed app opens in its own window with the
  app's icon and name

### Requirement: Offline app shell
A service worker (Workbox `generateSW`, `registerType: 'autoUpdate'`) SHALL precache the built
assets (HTML, JS, CSS, icons) so the app loads with no network after the first visit.

#### Scenario: Reopening offline
- **WHEN** the user has loaded the app once and later opens it with no network
- **THEN** the app loads normally and restores the persisted session

### Requirement: Automatic updates
When a new version is deployed, the service worker SHALL update itself and take over without asking
the user; the new version is used on the next load.

#### Scenario: New deploy
- **WHEN** a new version is deployed and the user opens the app
- **THEN** the new service worker installs in the background and activates, replacing the old cache

### Requirement: Update files are never cached by the host
`index.html`, `sw.js`, `registerSW.js` and `manifest.webmanifest` keep the same name across deploys,
so the host (S3/CloudFront via `Makefile`, nginx via `nginx.conf`) SHALL serve them with
`Cache-Control: no-cache`; otherwise browsers would never notice a new version.

#### Scenario: Deploy to S3
- **WHEN** `make deploy` uploads the build
- **THEN** those four files get `no-cache` and the hashed files in `assets/` get a 1-year `immutable` cache
